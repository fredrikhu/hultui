## Candidates

- **id: dialog-scrim-button-role** (correctness; perf on changes inside dialogs; Waiting, keep, first)
  - **What:** a clickable box whose child has the Dialog role is a backdrop, not a Button. This covers `Dialog.Show`'s scrim (and so every command palette) and Meridian's own Options backdrop (MeridianApp.Palette.cs:121).
  - **Evidence, the cause in code:**
    - `InferRole` makes a box with a click handler a Button (AccessibilityTreeBuilder.cs:654), so the scrim is named from all the dialog's text.
    - `RemakeLeaf` refuses a name change under an ancestor named from its content (:584).
    - So every label change inside a dialog fails its leaf patch. That builds the whole window's tree, not just the overlay's part (Window.cs:1607).
  - **Evidence, palette over 2,000 commands:** the scrim is a Button with a 2,182-character name, and every keystroke changes its Name: 40 changes in 40 keys. In Junction's palette: 30 in 30 keys, about 1,000 characters each.
  - **Evidence, label ticking in a dialog every 50 ms over 1,000 rows:** 40 trees in 40 ticks.

    | Per tick | Tree only | UIA | AT-SPI |
    |---|---|---|---|
    | Scrim with a click handler | 283.8 KB | 284.2 KB | 1,081 KB |
    | Without one | — | 1.8 KB | 400 KB |

  - **Evidence, Meridian-style in-tree modal:** any label change inside it costs 260.4 KB with UIA (1,058 KB with AT-SPI) and 1 tree. The in-place refresh fails too, with "a node with children changed".
  - **Expected:**
    - Correctness: a dialog is no longer read inside a "button", and a palette keystroke raises 2 Name events → 1 (UIA and AT-SPI).
    - Dialog tick: UIA 284.2 → 1.8 KB (−99.4 %), trees 40 → 0.
    - In-tree modal: 260.4 → 1.2 KB (−99.5 %), AT-SPI 1,058 → 1.4.
    - Palette key: UIA 454.8 → 441.9 KB (−2.8 %).
    - All numbers are from a prototype run.
  - **Cost:** small. The prototype (`HoldsDialog`: a direct child with `Role == Dialog`) passes all 1,134 Headless tests. No API change, no pixel change. What a reader hears changes (see Needs the user).

- **id: a11y-atspi-snapshot-per-diff + apps-scenario-atspi-rows** (Linux; churn and scaling; keep, re-measured)
  - **What:**
    - Keep the AT-SPI objects by id in a concurrent map, as UIA keeps its wrappers.
    - On each apply, point every object at its new node (a walk that allocates 0 B).
    - Make objects only for added nodes, and reuse child-path arrays whose child ids did not change.
    - Add AT-SPI suite rows (the suite needs an `InternalsVisibleTo` for PerfSuite).
  - **Evidence, cause:** every `ApplyChanges` rebuilds the whole snapshot (LinuxAccessibilityBridge.cs:246, :814), about 265 B per node. Since c9adbb6c, patches and in-place refreshes no longer go through it; three things still do:
    - every structural diff;
    - every tree whose diff is property-only;
    - every overlay part (Window.cs:1055 hands the whole tree to the bridge).
  - **Evidence, UIA vs AT-SPI per step:**

    | Scenario | UIA | AT-SPI | AT-SPI apply |
    |---|---|---|---|
    | Dialog tick, 500 ms (overlay part of ~30 nodes) | 2.6 KB | 799.5 KB | 797 KB at 3,006 nodes |
    | Palette over 2,000 commands | 454.8 | 1,338.1 | 928 KB |
    | Add a row to 1,000 rows | 268.8 | 1,075.5 | — |
    | List filter | 286.1 | 1,127.8 | — |
    | Tab switch | 299.8 | 573.5 | — |
    | Junction palette | 281.8 KB/key | 374.8 | 116 KB/key (UIA 23) |
    | Junction History search | 245.2 KB/key | 293.1 | 50.4 KB/key (UIA 2.3) |

  - **Expected:**
    - AT-SPI apply −95…−99 % where the change is small. The palette keeps about 45 KB of new objects, because its rows are remade.
    - AT-SPI step −60 % (palette) to −99.8 % (dialog tick).
    - Scaling: from O(nodes) allocated per apply to O(changed).
  - **Cost:** medium–large, Linux only. No API change. The signals stay the same. The bus thread must read objects the way UIA's threads read wrappers: each field swapped whole.

- **Evidence for palette-row-keys (expert 6; not mine).** Each palette keystroke removes and re-adds every visible row:
  - 200 nodes per key in the synthetic palette, 128 in Junction's;
  - so as many new UIA wrappers (apply 44.6 / 23.2 KB per key) and 2 structure events;
  - AT-SPI sends 504 / 264 signals per key (cache-remove, cache-add, children-changed).

  Keying rows by command would make a narrowing keystroke removals only.

## Examined, not worth it

- **a11y-box-selected-patch (close).**
  - Changing `AccessibleSelected` on a plain box builds a tree: 258.6 KB with UIA at 3,003 nodes.
  - But its only producer is `TabHeaderElement.Show` (TabsElement.cs:535), and a tab switch also swaps the panel: 901 nodes removed and re-added per switch, even with `KeepAlive`.
  - So a patch would never apply. No app sets it.
- **a11y-in-place-fallbacks (close).**
  - "A node with children changed" happened in 4 of about 1,150 refreshes over 7 suites.
  - The composite grid's fallbacks are real structure changes (+136/−136 nodes per 120 notches). The backoff keeps them to 20 trees per 120 notches.
  - Cost per notch over bridge off (3.6 KB): +1.0 KB tree, +1.4 UIA, +3.5 AT-SPI, at 41 nodes.
- **a11y-served-items-followups (performance part).**
  - Renaming the selected item of a 3,000-item list sends 0 events in 20 renames, on both bridges. DECISIONS records this choice.
  - The rest is a live Orca check (see Needs the user).
- **Button `IsEnabled` flip.**
  - A whole tree per flip: 259.0 KB with UIA, 1,055 with AT-SPI, at 3,003 nodes.
  - It happens about once per user action (Junction's commit button, Meridian's send).
  - A button's label child also rules out a leaf patch.
- **Junction History search typing.**
  - 1 tree per key: +28.7 KB with UIA (+13 %) and +76.6 with AT-SPI, on 216.5 KB with the bridge off.
  - About 45 Name events per key, because virtual items are named by index, so a filter renames the visible items.
  - The list is most of the 139-node tree, so rebuilding only the list would save under 5 % of a key. The AT-SPI part falls to candidate 2.
- **Tab switch wrappers.** 157 KB of UIA apply per switch (901 wrappers), once per user action.
- **Reader-pace walks.**
  - Item-row walk over 1,000 rows: 0 trees; +1.1 KB tree / +1.4 UIA / +1.8 AT-SPI over 6.6 KB off.
  - Junction History and Tags: 0 trees, +1.4…2.3 KB per key.
