## Examined, not worth it

- a11y-scrollpercent-role: real mechanism, but no ScrollViewElement in src/ or apps/ takes another role.
- Skipping rebuilds for range-value-only ticks: exact (422 KB → 0) but real progress UIs change a label in the same frame; folded into a11y-property-patch.
- a11y-eager-virtual-items as an exact change: needs one GetItemLabel per item per rebuild anyway; only on-demand provisioning helps (Needs the user).
- Rebase walk lookups (0 B); lazy UIA wrappers (~150 B/node retained, < 2 % of an app heap); `IsActive` P/Invoke (1–3 per frame).
- ElementNativePrimary race (pre-existing): a UIA thread can create a native object for a wrapper being dropped; rare, one-lock fix if wanted.
- a11y-atspi-cache-child-index: still unverified (needs live libatspi; `wsl` refused); stays Waiting.

## Needs the user

1. **Gate the Linux bridge on `org.a11y.Status`?** Today it is active whenever the AT-SPI registry is up (every GNOME/KDE session, no screen reader needed; LinuxAccessibilityBridge.cs:103, AccessibilityBridgeFactory.cs:21-27): a keystroke in a 603-node form costs 385 KB vs 3.2 KB with no bridge; creating 1,000 rows sends 3,001 cache-add signals. Gate `IsActive` on IsEnabled/ScreenReaderEnabled as Qt does (with an always-on override). Risk: clients that never set IsEnabled (plain pyatspi scripts, AtSpiVerify) see nothing.
2. **Provide list items on demand at any size?** Lists ≤ 2,000 items rebuild one node and one app label per item every rebuild: the walk step is 382 KB with UIA, 298 KB of it a11y (78 %); AT-SPI 1,022 KB. Trade-off: per-item Name, bounds and Added/Removed events become list-level invalidation.
3. **Drop the Value change for elements with a text pattern?** A rich text keystroke raises a UIA ValueValue change carrying the whole document (749,017 chars, ~1.5 MB BSTR) and an AT-SPI accessible-value with the whole text (~750 KB over D-Bus), besides TextChanged; TextArea likewise. Unlocks most of a11y-richtext-text-snapshot.
4. **Add range value events?** A Slider or ProgressBar value change raises nothing on either bridge; AT-SPI advertises no Value interface. A keyboard user moving VideoPlayer's Seek slider hears nothing. Add UIA RangeValue.Value changes and AT-SPI Value with accessible-value?
5. **Approve the added events** in a11y-focus-unbuilt-node (one missing focus event) and a11y-virtual-item-selected (IsSelected changes on two items per move).
