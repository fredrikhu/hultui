Objections, each now a candidate:

1. 240d468's −97 % holds only for a client that never reads text (the suite's recording bridge). Any
   read sets `_readerAsked` (RichTextEditorElement.Accessibility.cs:66) and every later version is
   made from the layout at once (:107-111). A UIA reader reading after each keystroke: 45.5 → 1,974 KB
   per keystroke; AT-SPI always 1,974 KB (text-changed needs both texts,
   LinuxAccessibilityBridge.cs:413-419). No regression against before (2,100 KB).
2. ff94faa/240d468: UiaFragment.cs:203 reads a text node's ValueValue live (UiaHostBridge.GetValue →
   Window.FindElement, Window.cs:611-629): an unsynchronized O(elements) walk of the live tree on a UIA
   worker thread, then `ToPlainText` on the live document (1.5 MB at 5,000 blocks). `Node.Value`
   (TextVersion.Value) gives the version the events describe, on any thread.
3. 2170222: AtSpiBus.cs:174 queues an independent pool read per PropertiesChanged; they write
   `_statusOn` (LinuxAccessibilityBridge.cs:131-135) in finish order. An on→off→on burst faster than
   one D-Bus round trip can leave the bridge off while Orca runs. Rare.
4. 7dc7e0e covers only eager lists (≤2,000 items). Over 2,000, 10 selection moves are told 0 times on
   UIA and AT-SPI (1,500 items: 19 events). SelectedIndex still forces a whole-tree rebuild per move
   for an empty diff.

**Note for runtime-idle-wakeups (expert 4):** the 250 ms range deadline (Window.cs:143) and the trailing
layout deadline rely on the 16 ms idle wait (Application.cs:533); `MakeFromLayoutSoon` posts wake the

## Candidates

- **a11y-item-label-keep.** A list on item rows (`RenderWith((item, selected))`) keeps each item's a11y
  label while the item (EqualityComparer) and the label delegate are unchanged; InvalidateRows or new
  Items clear it. AccessibilityTreeBuilder.cs:296 calls `GetItemLabel(i)` for every item every rebuild
  (VirtualListElement.cs:145), running app lambdas such as `$"{c.Subject}, {c.AuthorName},
  {c.ShortHash}"` (JunctionApp.History.cs:1000, on item rows since 73b1c10; the suite's WalkPane).
  Probe, 1,000 item rows, one move per step: build+diff 248.8 → 90.8 KB/step (−63.5 %); UIA 249.2 →
  91.2; AT-SPI 545.8 → 387.8 (−29 %); bridge off 4.3 KB, so a11y is 98 % of the step. Churn −63 % on a
  new row "a11y/selection walk 1,000 item rows, bridge on"; time likely ≥5 %. Small; no API change, but
  extends the item-rows contract to labels (an impure label stays stale until InvalidateRows, as a kept
  row does). Proof: Core tests after item change, new Items, InvalidateRows, new delegate; UIA and
  AT-SPI streams and tree dumps of the walk scripts identical.
- **a11y-patched-props-untold.** Role, AccessibleName, AccessibleDescription, AccessibleExpanded and
  AutomationId setters notify the a11y observer on change, as AccessibleSelected and AccessibleToggled
  do. They are plain auto-properties (Element.cs:24, 658, 659, 667, 704); since 785e698 (2026-10-06,
  before plan 17) patching Box/Text/Image/ScrollView (BoxElement.cs:82, TextElement.cs:514,
  ImageElement.cs:148, ScrollViewElement.cs:408; Element.cs:1326) marks no layout, so a rebuild that
  changes only these is never told. Probe (component rebuild, then 30 frames): Box name "Inbox (0)" →
  "(1)" 0 diffs; Group → Dialog 0; description 0; expanded 0. A Canvas name is told only through the
  accidental layout refresh (1 diff), which a11y-layout-refresh-moved-only removes. Real cases:
  Aperture's "Quality: …" and "Downloading, …" boxes (masked today by sibling text changes);
  VideoPlayer Play/Pause (Canvas). Correctness; perf neutral; prerequisite of
  a11y-layout-refresh-moved-only and a11y-property-patch. Small; adds Name, Description and
  ExpandCollapse events. Proof: a test per property (UIA and AT-SPI gain exactly that change within one
  frame); every other standard script identical.
- **a11y-layout-refresh-moved-only.** Skip the coalesced a11y bounds refresh (Window.cs:968) when the
  layout pass moved or resized no element. Any component rebuild that patches a type not opted into
  PatchMarksOwnLayout sets layoutWasDirty, rebuilding the whole a11y tree every 100 ms for an empty
  diff. Probe A, whole-app tween rebuild per frame (Junction spinner/toast pattern), 300 rows: a11y
  builds 26 → 1 per 150 frames; 8.7 KB/frame → 0 (740.8 → 732.1 KB/frame = bridge off); a shadow full
  rebuild after each of the 150 frames gave 0 non-empty diffs. Probe B, playing VideoPlayer 10 s: 110
  builds, 81 empty (applied: RangeValue 20, Name 9); 8.1 attached layout marks per frame from patches of
  VideoElement, VideoPlayerRootElement, 4 CanvasElement icons, 2 SliderElement. Removes a per-frame
  allocation from animating frames with a reader (~258 KB per refresh at 3,001 nodes). Small–medium: a
  flag at the layout engine's final box writes (LayoutEngine.cs:404, 1568, 1582; LayoutEngine.Grid.cs:124)
  comparing against the previous pass (intermediate writes go A→B→A, so compare final boxes). Needs
  a11y-patched-props-untold first. No pixel impact. Proof: shadow mode (full rebuild + diff at every
  skipped refresh, assert empty) over Headless, Media and app headless suites; streams identical.
- **a11y-atspi-cache-child-index.** One children-changed:add per added child, unless the added run ends
  its parent's children. Live in WSL: two siblings inserted at once in the middle → cached [A, X, Y],
  real [A, X, Y, B, C] (B and C lost to the cache); one in the middle, two at the front, two at the end,
  or two in the middle in separate frames: cached = real. Cause: one coalesced signal per parent
  (LinuxAccessibilityBridge.cs:295-307). Correctness; extra signals only for middle inserts, bulk
  appends stay coalesced. Small. Proof: r3 live driver (cached == fresh in all six cases), AtSpiVerify
  bulk, AtSpiSignalTests.
- **a11y-role-change.** The differ compares Role; UIA raises ControlType (and LocalizedControlType)
  property changes, as Chromium does for ROLE_CHANGED; AT-SPI sends property-change:accessible-role
  (already sent for IsPassword, LinuxAccessibilityBridge.cs:392-396). AccessibilityTreeDiffer.cs:120-200
  never compares Role. Live: after Group → Dialog the caching client still reads "panel" (fresh:
  "dialog"), and back again; UIA raises nothing (since 2235e4a it answers the new role on request).
  Correctness. Small; patched roles also need a11y-patched-props-untold. Proof: live driver role case
  cached == fresh; UIA test; other streams identical.
- **apps-scenario-atspi-rows.** Perf-suite rows with the AT-SPI bridge on recorded signals
  (InternalsVisibleTo for PerfSuite, or a test seam), any OS. Per-step AT-SPI cost is 2.2–4.1× UIA's
  and timed nowhere: TextInput 214.7 vs 53.6 KB; checkbox 352.3 vs 87.2; label 706.4 vs 173.5; wheel
  1,054.4 vs 260.5; walk 545.8 vs 249.2. Measurement for a11y-atspi-snapshot-per-diff. Small.
- **a11y-atspi-snapshot-per-diff.** Per-element AT-SPI objects rebased onto the current node each
  apply, as UIA wrappers since 42098f1: path cached per element, child paths read from node.Children
  on demand, path index updated from Added/Removed. Every apply rebuilds every object
  (LinuxAccessibilityBridge.cs:208, 454-482) at 265 B/node, against UIA's 0.3–0.5 KB apply:

  | Step | Nodes | AT-SPI apply |
  |---|---|---|
  | Keystroke | 603 | 159.1 KB |
  | Checkbox | 1,001 | 265.3 KB |
  | Label edit | 2,001 | 533.3 KB |
  | Wheel | 3,001 | 795.9 KB |
  | Walk | 1,002 | 296.9 KB |

  Paid only while Orca runs (2170222), but then every a11y frame. AT-SPI apply −99 %; Linux a11y step
  −56…−75 %, down to UIA's level. Medium–large, Linux only, no API change. Proof: every object answers
  as the old snapshot builder over standard scripts and random trees; signal streams identical; live
  tree dump identical in WSL; AtSpiVerify bulk.
- **a11y-virtual-items-and-selection.** AT-SPI serves a virtual container's items on demand
  (ChildCount, GetChildAtIndex/GetChildren; objects read through the host, as UiaVirtualItem does).
  The container node carries the selected index, so a move raises UIA SelectionItem_ElementSelected on
  the virtual item and AT-SPI state-changed:selected. Live: a 3,000-item list has 0 children (cached
  and fresh); 1,500 items have 1,500. Over 2,000 items a move is told 0 times on both bridges
  (AccessibilityTreeBuilder.cs:257-264; Linux walks Children only, LinuxAccessibilityBridge.cs:471-482).
  Affected: Junction History past 2,000 loaded commits; Vesper folders over 2,000 files. Correctness;
  no per-item cost; only lists already on demand (not the declined "items on demand at any size").
  Medium; added events. Proof: live driver reads 3,000 children matching the eager path's names, roles,
  states; move events match the eager path.
- **a11y-uia-text-value-from-node.** UiaFragment answers a text node's ValueValue from `Node.Value`
  (the version), not through Window.FindElement (objection 2: UiaFragment.cs:203, UiaHostBridge.cs:53-61,
  Window.cs:611-629). Thread safety; removes an O(elements) walk and a live `ToPlainText` (1.5 MB) per
  read. Small. Proof: UiaTextPatternTests, RichTextTextOnRequestTests; the value equals the version the
  text events describe.
- **a11y-atspi-status-serialize.** One status reader loop that re-reads while changes arrived, or
  values taken from the signal body (objection 3, AtSpiBus.cs:159-176). Correctness (rare). Small.
  Proof: AtSpiStatusTests with interleaved on/off bursts; live driver status script.
- **a11y-textarea-text-pattern.** TextArea offers text (versioned, like the editor's) and, under
  ff94faa's rule, tells a keystroke as a text change only. A keystroke in a 2,000-line TextArea raises a
  UIA ValueValue change of 121,744 characters (243 KB unmanaged BSTR) and an AT-SPI accessible-value of
  the same length; managed a11y bytes add only 1 KB. Scaling O(text) → O(1) per keystroke only if the
  Value change is dropped (Needs the user); otherwise correctness only. Small–medium. Proof: UIA and
  AT-SPI text-pattern tests; streams identical except the documented Value → TextChanged swap.
- **a11y-richtext-reader-keystroke.** AccessibleText over the document's blocks (no flat string per
  version; range, word and line reads from blocks; line geometry per visible range), and AT-SPI
  text-changed computed from the two documents' block identity (objection 1). With a reading reader a
  keystroke in a 5,000-block document costs 1,974 KB on both bridges: the 1.5 MB plain text (new per
  document) plus ~470 KB of tables (BuildAccessibleText, :265-341). About −90 % per keystroke while a
  reader reads. Large: AccessibleText is public; `Text` becomes lazy; UiaTextProvider and AtSpiText move
  to span reads. Proof: an equivalence corpus where every UIA text-range call and AT-SPI Text call
  (units, boundaries, extents, offset at point) answers identically over random documents and edits;
  streams identical.
- **a11y-property-patch.** Rebuild only notified elements' nodes on property-only frames. Build+diff
  share of a step with the bridge on (AT-SPI applies come on top): keystroke 603 nodes 52.3 of 55.6 KB
  (94 %); checkbox 1,001 nodes 86.4 of 86.9 (99 %); label edit 2,001 nodes 172.2 of 173.1 (99 %); walk
  1,002 nodes 244.5 of 248.8 (98 %). O(n) → O(changed), −95 %+ of those bytes. Large; needs
  a11y-patched-props-untold and, on Linux, a11y-atspi-snapshot-per-diff. Proof: the shadow mode of
  a11y-layout-refresh-moved-only across all headless suites.

## Examined, not worth it

- a11y-videoplayer-layout-refresh alone: the cause is patch layout marks (8.1 attached per frame); the
  a11y cost is 0.67 KB/frame (41.11 → 41.78) in a ~25-node tree. Folded into
  a11y-layout-refresh-moved-only. **Lead for expert 1:** opt CanvasElement, SliderElement, VideoElement
  and subclasses into PatchMarksOwnLayout, removing a layout pass per playing frame (VideoElement alone:
  4,882 → 4,273 marks per 10 s).
- a11y-atspi-richtext-tables alone (exact arrays, no '\n' rescan): ~190 KB of 1,974 (−10 %); superseded
  by a11y-richtext-reader-keystroke unless that is declined.
- Progress ticks after 444ba70: 4 rebuilds per 60 frames; 17.2 KB/frame average (AT-SPI 70.4). As
  designed.
- AT-SPI real bus vs the recorder: the snapshot dominates (~580 KB per command at ~1,515 nodes,
  consistent with 265 B/node); signal marshalling negligible.
