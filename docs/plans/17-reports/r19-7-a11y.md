REVIEW:

- **8b7471c8 (disconnects on their own thread), objection: items served on demand skip the "tell the old one first"
  guard, and a reader loses a focus event.**
  - An eager item node and a served item share one runtime id: `VirtualItemId.ForSlot(slot, index)`.
  - When a list crosses from ≤200 items to >200, the apply hands the removed eager item providers to the worker. In the
    same frame the focus event is raised on a new `UiaVirtualItem` with the same runtime id.
  - `TellFirst` guards only `ElementRef` (UiaFragment), not `NativeVirtualItem`/`NativeVirtualItemSimple`. When the
    worker's `UiaDisconnectProvider` lands after the raise, the client can't read the focused element.
  - **Vesper, a 3-entry folder into a 1,001-entry folder, reader-like client:** the client's first read of the focused
    item failed (COMException ELEMENTNOTAVAILABLE) in 4 of 12 crossings on the base (holds 1 and 4). A reader would say
    nothing on entering the folder.
  - **Prototype** (TellFirst on served-item creation when anything is untold): 0 of 9 lost.
  - Before 8b7471c8, every disconnect ran before the raises.
- **8b7471c8, otherwise verified in real windows.**
  - 0 disconnects on the UI thread in 13 launches with a client; the worker told 37.
  - TellFirst through `ElementRef` ran 0 times.
  - At every close, `Dispose` found 0 untold, and `TellNow` took 0.001 ms.
  - Junction's palette close, 13–14 disconnects on the worker: frame 3.0–3.4 M cycles, a11y 0.58–0.68 M (round 18,
    synchronous: 25.7 M).
  - The worker's calls take 15–650 µs, so it makes no blocking cross-thread send to the UI thread; the 2 s spin cap in
    `Dispose` stays theoretical.
- **5b7a4494, 421cc677 (Aperture's focus handover): no objection.**
  - **How measured:** headless HeadlessUiaReader (the real UIA bridge), 63 films, ×2 with and without the reader,
    identical.
  - Each way into a page sends 1 focus event with a name: key 2 "Film number 0, 1990"; Enter "Play Film number 17";
    Escape back to the library its card; Escape to Home "Resume Solaris…"; Digit1; Alt+Left and Alt+Right.
  - A rail click sends 2 events in 2 frames: the rail button "Series (3)", then the card. That is by design (the card
    gets the keyboard after the build).
  - Bridge bytes per page change: +15–83 KB. Disconnects: 5 at Enter, 2 at each later change.
  - Both of round 18's NEEDS THE USER items are closed by 5b7a4494.
- **3442c3f5, 30a53f02: no objection.** The a11y builder and the bridges read neither `ContextMenuItems` nor event
  handlers (a label's role comes from its own properties), so the tree and the events are unchanged after a patch.
- **d9bf8e25 (menus from the keyboard), objection (keyboard and reader, not perf).**
  - **What a reader hears** (headless, Junction History; the menu opened with `Window.OpenContextMenu(row)`):
    - Opening: a focus event on the first MenuItem ("Checkout this commit (detached)"), 2 HasKeyboardFocus changes and 1
      structure event.
    - Each arrow or type-ahead move: 1 focus event and 2 HasKeyboardFocus changes; 0.6–3.1 KB with the reader, 0.1 KB
      without.
    - End on the last item: nothing. Escape: a focus event back on the commit row, and 6 disconnects, now on the worker.
  - **Objection:** in Junction, Shift+F10 and the Menu key open nothing (0 raises, 0.2 KB). All 18 of Junction's menus
    are on rows, under a focused VirtualList. `FindContextMenuOwner` walks up from the list and never into its current
    row. The list's `CurrentIndex` is −1 anyway (Junction moves `SelectedIndex`).
  - Vesper, Aperture and Meridian handle these keys themselves.
- **11554b8b (`&` mnemonics), two objections.**
  - **Access keys are not exposed:** no UIA AccessKey property and no AT-SPI key binding, for menu items or buttons. No
    app uses `UseMnemonic`.
  - **Lead for the painting expert:** Alt down and Alt up each mark the root paint-dirty (`SetMnemonicCues`) in every
    app. That is 1 extra frame per Alt press headless (0 for Shift), and 2 in a real window when Alt is let go
    separately. Yet no app uses `UseMnemonic` or `MenuBar`.
- **ab8a2050: no objection.** The sort reaches readers in the header names and one announcement. No app uses TableView.
- **bd3605ff: one lead.**
  - ScrollbarElement's range raises go through the window's 250 ms coalescing; a double holds the value exactly up to
    2^53.
  - **Lead:** `CanvasElement.NotifyTextSourceChanged` with an app's (non-versioned) source sets `_a11yPropertyDirty`.
    That refreshes the whole tree for each notify. See the candidate below.

CANDIDATES:

- id: a11y-served-item-tell-first
  what: Tell an eager item's old provider gone before a served item with the same runtime id is made or raised on,
  ideally by queueing that raise behind the tell on the worker.
  evidence:
  - Real window, Vesper 1240×820, the 1440p at 100 %, 200 Hz.
  - Base: 4 of 12 crossings into a >200-entry folder lost the focus event. Prototype (`TellFirst` in
    `NativeVirtualItem*`): 0 of 9.
  - The prototype's catch: it told 1 provider on the UI thread in 1 of 3 crossings, at 4.5–4.7 ms wall (11 M cycles) in
    that frame. That crossing's frame went from 1.7–2.0 ms to 6.0–6.2 ms.
  real app: Vesper, every folder change from a folder of ≤200 entries into one of >200, with any UIA client asking
  (Narrator, NVDA, Magnifier).
  expected: correctness: a regression from 8b7471c8 closed. A queued raise keeps the 4.5 ms off the UI thread; the
  prototype's form costs less than before 8b7471c8, when every disconnect ran synchronously.
  cost: small (prototype form) to medium (queued raise). No API, no pixels.
- id: a11y-item-renames-unfetched (promoted from Waiting)
  what: Raise no Name change for an eager item node that has no native object yet: one no client was ever given.
  evidence:
  - Real window, Vesper, navigating between a 151-entry and a 191-entry folder (both eager, ≤200): 153–154 Name raises a
    navigation.
  - **What a navigation costs:**

    | Client | Frame wall | a11y block | Name raises | UI-thread provider calls | Frame cycles |
    |---|---|---|---|---|---|
    | Reader-like | 6.6–6.7 ms | 5.4–5.6 ms | 5.0–5.2 ms | 12,300 (plus 13,800 QIs) | 19–24 M, a11y 78–85 % |
    | Focus-only | 4.1–4.4 ms | 1.8–2.4 ms | 1.6–2.0 ms | 3,700 | — |
    | Bridge off (`HULTUI_A11Y=0`) | 1.35–1.41 ms | — | — | — | 3.0–4.6 M |

  - A Name raise costs 25–33 µs (reader-like) or 10–13 µs (focus-only), almost all UIA's own work. Headless runs never
    showed this.
  - After the first navigation, 160 native objects and 262 wrappers persist: the first rename raise makes them and hands
    them to the client. So the rule must be "no native yet"; items no client fetched then never get one.
  - Served lists (>200) raise no renames: a 1,001 ↔ 1,000 navigation made 9 property raises.
  real app: Vesper Enter or Backspace between folders of ≤200 entries, the common case, every navigation, with a reader
  running.
  expected: the time bar. The navigation frame goes from 6.6 to about 1.7 ms with a reader-like client (about −75 %), and
  about −60 % focus-only. The remaining raises (bounds, keyboard focus, selection, the focus event) cost about 0.4 ms, as
  a navigation between two served folders does.
  cost: small. No API, no pixels. A client listening for Name changes on the subtree no longer hears renames of rows it
  was never given; NVDA's global handler would get 153 fewer events, which it ignores.
- id: a11y-canvas-text-notify-patch (low)
  what: Route `CanvasElement.NotifyTextSourceChanged` through the per-element text patch (`_a11yTextChanged`, as the
  versioned text area does) instead of marking the whole tree property-dirty.
  evidence: Headless HeadlessUiaReader, 20 steps of a 60×160 screen. Each step raises 1 TextChanged event. Bridge bytes:
  +0.7 KB a step alone, +52.3 KB a step beside 600 labels (O(window elements) per scroll step).
  real app: none yet. This is the new API for documents too large to lay out; the scaling argument applies to a big-file
  viewer that adopts it.
  expected: the scaling bar (O(n) per scroll step removed), with a reader only.
  cost: small. No API.
