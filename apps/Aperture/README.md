# Aperture

A native Jellyfin client: your server's libraries as shelves of artwork, and the
framework's own video player behind the Play button. No browser, no Electron —
the same HultUI shell the other three apps are built from, with the picture
decoded by libmpv.

Two projects:

| Project | What it is |
|---|---|
| `Aperture.Core` | The server side: the connection, the session, and one `IMediaLibrary` the views talk to. Built on the official **Jellyfin.Sdk** (Kiota-generated), with Aperture's own vocabulary over it — no SDK type reaches a view. No UI reference. |
| `Aperture` | The app (HultUI + HultUI.Media): Home, a library grid, an item page, search, settings, and the player sheet. |

## The shape

```
Connect  ──►  Home ──► Library grid ──► Item page ──► Player (a sheet, not a view)
                │                          │
                └── Search, Settings ──────┘
```

- **Home** is Continue watching, Next up, then what each library has added. Rows
  page sideways with two buttons rather than scrolling — a horizontal scroller
  nested in the page's vertical one is the framework's wheel-capture trap.
  That order is a default: the menu in each row's heading moves it, hides it, or
  folds the two “what now” rows into one “Up next”. The choices are keyed by row
  in the settings file, and a hidden row is listed at the foot of the page with a
  button that brings it back.
- **The grid** is rows of posters through a `VirtualListElement`, so a library of
  thousands realizes only the rows on screen and only those ask for artwork.
  Paging follows the viewport: the row that scrolls in asks for the page that
  would hold it.
- **The player** is a sheet over whatever you were looking at, so stopping a film
  puts you back where you started it with the navigation stack intact.

## Signing in

**Signing in** takes a password or a code. Quick Connect asks the server for a
six-character code, shows it, and polls on a timer until someone approves it on a
client that is already signed in — nothing secret is typed into this window, which
is what makes it the right door on a shared machine or a television.

The address is what people actually type. `jellyfin.home` is tried on port 80,
then **8096** — Jellyfin's own port, and the reason a bare hostname otherwise
answers "connection refused" on a stock install — then the same two over HTTPS.

What is kept, and where:

| | Where |
|---|---|
| Server address, id, user name, device id | `%APPDATA%\Aperture\settings.json` (XDG on Linux) |
| Access token | the OS credential store (Windows Credential Manager) |
| Password | nowhere — it is used for one request and dropped |

A machine with no credential store signs in each launch, and says so rather than
pretending it saved.

## Playback

Pressing Play asks the server how the item can be played (`/Items/{id}/PlaybackInfo`),
which is where a server decides to transcode, and hands the resulting URL to
`MediaPlayer`. Direct play streams the original file; a transcode is labelled as
such in the title strip, because the two feel identical until something stutters
and then it is the first question.

**Artwork is anonymous, scrubber sheets are not.** Jellyfin serves `/Items/{id}/Images/...`
without authentication, which is why the poster cache is a plain HTTP fetch; a trickplay
sheet is behind the session and this server answers `?api_key=` with **401**, so the cache
carries the session's `Authorization` header instead. Putting a token in a URL was the wrong
instinct anyway — URLs end up in logs and caches.

**The scrubber is cut into chapters** when the file has marks, and fills to the pointer as
it crosses, so where you would land reads differently from where you are.

**Scrubbing shows a still.** Where the server has generated trickplay images, pointing at
the scrubber shows the frame for that position. Jellyfin packs them as sprite sheets — one
JPEG holding a grid of stills, one every ten seconds — so scrubbing a two-hour film costs a
handful of downloads rather than seven hundred; `TrickplayInfo` turns a position into a
sheet and a rectangle inside it, and the sheets go through the same bounded cache as the
posters. The chapter list shows the pictures the server extracted for the marks, when it
has them. Both are generated by scheduled tasks, so a fresh library has chapters and
scrubbing long before it has pictures of either, and both simply do not appear until then.

Settings → Playback → Quality caps the stream. **A bitrate on its own is
advisory**: with no device profile to evaluate, this server hands back the file and
the ceiling means nothing (measured against 10.10). So a capped request also sends a
profile that can direct-play nothing and transcodes to H.264/AAC over HLS — which is
what turns "keep it under this" into real re-encoding. Changing the ceiling re-opens
what is playing at the position it had reached.

Playback is reported back the way Jellyfin's own clients report it — started,
progress every ten seconds and on every pause, stopped — which is what drives
"now playing" in the dashboard, the Continue watching row, and the resume point
on every other device. Resume seeks client-side once the backend has loaded: the
stream URL always starts at the first byte.

## Requests (Jellyseerr / Seerr)

Connect a request server under **Settings → Requests** and the rail grows two buttons.
**Discover** is the server's shelves — trending, popular, coming soon — as the same posters
as the library's, each marked with where it stands: in the library, asked for, on its way.
**Requests** is who asked for what, with Approve and Decline for someone allowed to, and
Withdraw for your own while nobody has acted on it. Search asks both servers at once, so a
film the library does not have is one click from being asked for.

A title the library has opens the *library's* page, with its Play button — the request
server's `jellyfinMediaId` is the join. A series with some seasons in opens the discovery
page instead, which offers both the library and the seasons still to ask for.

A series in the library that is missing seasons says so on its own page, with a Request button
beside Play; something being downloaded shows how far it has got; and an allowance that is
nearly spent is said before the button is pressed.

Discover follows the request server administrator's own layout — its order, its switched-off
rows, its custom rows (streaming-service rows among them) — with genre rows that open genre
pages, studio and network rows of
logos that open everything a studio made or a network aired, and a name in a title's cast
opens everything that person is in. A bookmark keeps a title on the watchlist. Someone the
server lets choose can send a request to a particular Radarr or Sonarr, quality and folder.
Something wrong with what is playing (no sound, the wrong subtitles) is reported from the
player's title strip, and whoever looks after the library reads the reports under **Issues**
— a rail button (with a count of open ones) for someone the server lets read everyone's: the
conversation, a reply box, Resolve and Reopen. Whoever reported it has **Your reports** instead:
their own, with a mark (and a toast) when one has been answered or resolved since they last
read it. And when something you asked for arrives, the app says so — the server
has no push channel, so it looks every few minutes, and says each arrival once.

**It speaks the one API Jellyseerr 2.x and Seerr 3.x share** (Seerr is what Jellyseerr and
Overseerr merged into in February 2026). There is no .NET client on NuGet, and the published
OpenAPI spec leaves out exactly the fields Aperture reads (`jellyfinMediaId`, per-season
status, request seasons) and gets status 6 wrong — so the client is hand-written over
`HttpClient` with a source-generated `System.Text.Json` context, the same shape as Junction's
GitLab client, and native-AOT safe for the same reason.

Signing in, three ways, in the order offered:

| | What is kept |
|---|---|
| **Your Jellyfin account, nothing typed** (Seerr 3.4+). The server opens a Jellyfin Quick Connect request; Aperture approves the code itself with the session it already holds. | the session cookie, in the OS credential store |
| **Your Jellyfin password**, for Jellyseerr 2.x or a Jellyfin with Quick Connect off. Sent once. | the session cookie |
| **The server's API key.** It is the administrator's, so Aperture finds your Jellyfin user among the server's users and acts as them (`X-API-User`); requests land in your name. | the key |

The session cookie lasts 30 days; after that Settings asks again. The request server is
paired with the Jellyfin server it fills — signing out of one closes the other, and
forgetting the Jellyfin account forgets its request server too.

Artwork comes from TMDB, or through the server's own image cache when its administrator
turned that on. **The poster cache only ever sends the Jellyfin session header to the
Jellyfin server** — it used to send it to any host, which was harmless while every poster
came from Jellyfin and would have handed the token to TMDB the moment discovery posters did.

To look at it without a server, `--seerr-demo` mounts a fixture request server beside the
fixture library; `--seerr <address> --seerr-api-key-file <path>` uses a real one:

```bash
dotnet run .claude/skills/run-hultui-app/driver.cs -- --app aperture --seerr-demo --out shots 'click:@Discover' shot:discover
```

and `--probe` reads one from the command line, read-only, which is also the native build's
smoke test for this client:

```bash
dotnet run --project apps/Aperture/Aperture -- --probe jellyfin.home --api-key-file ~/jf.key --seerr seerr.home --seerr-api-key-file ~/seerr.key
```

## Installing it

Tagging `aperture-v<x.y.z>` builds a Windows installer and publishes it as a release
(`.github/workflows/aperture-installer.yml`). It packages the **Native AOT** publish —
one executable, no runtime to install — with the trimmed LGPL libmpv beside it, so
playback works out of the box rather than after a hunt for a decoder. Per-user by
default, so no UAC prompt for an unsigned installer.

Locally, the same thing:

```bash
dotnet publish apps/Aperture/Aperture -c Release -r win-x64
```

```bash
"%ProgramFiles(x86)%\Inno Setup 6\ISCC.exe" /DAppVersion=0.1.0 apps\Aperture\Installer\aperture.iss
```

(Copy `libmpv-2.dll` and a `LICENCE-mpv.txt` into the publish folder first — CI pulls
both from the `mpv-natives-ci` release.)

## Running it

```bash
dotnet run --project apps/Aperture/Aperture
```

**Diagnosing a server without a window**, which is also the smoke test for the native
build — everything it does goes through Kiota and System.Text.Json, the parts AOT could
break:

```bash
dotnet run --project apps/Aperture/Aperture -- --probe jellyfin.home --api-key-file ~/jf.key
```

```
jellyfin 12.1.0 at http://jellyfin.home:8096
signed in as fredrik
2 libraries: Movies, Shows
read "Guardian Fitz": 9 chapters, 1 trickplay widths, artwork tag True
```

Without a libmpv the app still runs — browsing, artwork, everything but the
picture — and the Settings page says the decoder is missing. See
`src/HultUI.Media.Mpv/README.md` for where it looks.

To look at it without a window, the screenshot driver mounts the same tree:

```bash
# a fixture library, no server needed
dotnet run .claude/skills/run-hultui-app/driver.cs -- --app aperture --out shots

# a real server, signed in with an API key from Dashboard → API Keys
dotnet run .claude/skills/run-hultui-app/driver.cs -- --app aperture \
  --server http://jellyfin.home:8096 --api-key-file ~/jf.key --out shots settle:2000 shot:home
```

## Tests

```bash
dotnet test tests/Aperture.Tests
```

The live tests skip themselves unless `APERTURE_LIVE_SERVER` and
`APERTURE_API_KEY` (or `APERTURE_API_KEY_FILE`) are set — and the request-server ones
unless `APERTURE_SEERR_SERVER` and `APERTURE_SEERR_API_KEY` (or `_FILE`) are; those are
read-only, and never request anything. They exist because the
part of a client that breaks is never the part a fake can model. One of them
caught the thing this whole app turned on: **Jellyfin writes ids without dashes**,
which the SDK's JSON reader refuses. `Aperture.Core/JellyfinSerialization.cs` is
the fix, and it is why the client works at all.

## The look

**Halide** (`Theme/Halide.cs`) — near-black ground, warm off-white text, one
projector-amber accent. Two rules: the artwork is the brightest thing on screen,
and the accent is a mark rather than a surface. Sibling to Nocturne (Vesper), the
Junction register and Azimuth (Meridian).
